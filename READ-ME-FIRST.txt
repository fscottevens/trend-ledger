STONKS RUN - MOVE TO CLOUDFLARE HOSTING  (update of Nov 4, 2026)
================================================================

WHAT CHANGED
------------
The site moves from GitHub Pages to Cloudflare (the same account that already
runs the scan scheduler and holds the stonks.run domain). Each scan now:

  1. restores the scan state from a new "data" branch
  2. runs the scanner (unchanged rankings)
  3. saves the state back to the "data" branch (one commit, replaced each run,
     so the repo stops growing by ~380 KB every hour)
  4. builds the site with tools/build_site.py:
       - clean addresses (stonks.run/history instead of history.html; the
         old addresses redirect permanently, so no links break)
       - the two lists are baked into the home page, so Google and slow
         phones see real rankings instead of an empty "Loading" table
       - one page per stock (stonks.run/stock/nvda), ~890 of them, plus a
         directory at stonks.run/stock/ - new search traffic + ad space
       - sitemap, robots.txt and security/caching headers
  5. deploys to Cloudflare

Nothing changes for visitors until you flip the switch in PART 4. Until then
stonks.run keeps running on GitHub Pages exactly as today, and the Cloudflare
copy runs side by side at a preview address for you to check.

Steps 2-6 work from a phone browser. Only PART 1 may need the computer,
depending on how the code reached GitHub.


PART 1 - MAKE SURE THE NEW WORKFLOW IS IN PLACE
-----------------------------------------------
Open https://github.com/fscottevens/trend-ledger/blob/main/.github/workflows/scan.yml
It should contain a step called "Save scan state to the data branch".

If it does NOT (GitHub sometimes refuses workflow files from tools), the new
version is in scan.yml.COPY-INTO-.github-workflows. On the computer:

  cd C:\Users\fscot\Documents\trend-ledger
  git pull
  copy /Y scan.yml.COPY-INTO-.github-workflows .github\workflows\scan.yml
  findstr /C:"data branch" .github\workflows\scan.yml
  git add -A
  git commit -m "Workflow: build and deploy the site to Cloudflare"
  git push

(The findstr must print a line. If it prints nothing, the copy failed.)


PART 2 - CLOUDFLARE API TOKEN  (about 3 minutes)
------------------------------------------------
1. Go to https://dash.cloudflare.com/profile/api-tokens
   (profile icon, top right > My Profile > API Tokens).
2. Create Token > find the "Edit Cloudflare Workers" template > Use template.
3. Account Resources:  Include > your account.
   Zone Resources:     Include > Specific zone > stonks.run
4. Continue to summary > Create Token. COPY the token (shown only once).

Then add it to GitHub:
5. https://github.com/fscottevens/trend-ledger/settings/secrets/actions
   > New repository secret
       Name:   CLOUDFLARE_API_TOKEN
       Secret: (paste the token)
   > Add secret


PART 3 - FIRST RUN + CHECK THE PREVIEW  (about 10 minutes, mostly waiting)
-------------------------------------------------------------------------
1. https://github.com/fscottevens/trend-ledger/actions > "Scheduled scan"
   > Run workflow > Run workflow.
2. Wait for the green check (~5-6 minutes). In the run, the "Deploy to
   Cloudflare" step ends with a line like
       https://stonks-run.fscottevens.workers.dev
3. Open that address and check:
     - the home page shows both lists
     - "Stocks" in the menu opens the directory; a stock page opens from it
     - clicking a ticker on the home page opens its stock page; clicking the
       rest of the row still opens the pop-up breakdown
   (The preview hides itself from Google, so it can't compete with stonks.run.)

If the run fails at "Restore scan state" or "Save scan state", nothing was
lost: the site keeps its last data. Send me the error text from that step.


PART 4 - FLIP THE SWITCH  (2 minutes + a few minutes for DNS)
------------------------------------------------------------
1. https://github.com/fscottevens/trend-ledger/settings/variables/actions
   > New repository variable
       Name:  SITE_HOST
       Value: cloudflare
2. Actions > "Scheduled scan" > Run workflow again.
   This deploy attaches stonks.run and www.stonks.run to the Cloudflare
   Worker. Cloudflare replaces the old GitHub Pages DNS records by itself.
3. After the run is green, open https://stonks.run/stock/ . If it loads,
   stonks.run is now served by Cloudflare (GitHub Pages has no such page).
   Give it 5 minutes and refresh if it 404s at first.

From now on the scans stop committing data to main. Your git pulls get much
smaller.

IF SOMETHING LOOKS WRONG AFTER THE SWITCH (rollback)
  a. Delete the SITE_HOST variable (or set it to github).
  b. Cloudflare > Workers & Pages > stonks-run > Settings > Domains & Routes:
     remove stonks.run and www.stonks.run.
  c. Cloudflare > stonks.run > DNS: add back the GitHub Pages records
       A     stonks.run  185.199.108.153   (and .109.153, .110.153, .111.153)
       CNAME www         fscottevens.github.io
  GitHub Pages keeps the last data it had until the next scan commits again.


PART 5 - AFTER THE SWITCH  (any time, ~15 minutes total)
-------------------------------------------------------
A. Turn off GitHub Pages:
   https://github.com/fscottevens/trend-ledger/settings/pages
   > Source: change "Deploy from a branch" to None (or Unpublish).

B. Redirect www to the main address (so Google sees one site, not two):
   Cloudflare > stonks.run > Rules > Redirect Rules > Create rule
   > use the template "Redirect from WWW to root" > Deploy.
   While you're in the stonks.run zone: SSL/TLS > Edge Certificates >
   "Always Use HTTPS" > On.

C. Visitor analytics (free, no cookies, no consent banner needed):
   Cloudflare > Analytics & Logs > Web Analytics > Add a site > stonks.run.
   - If it offers automatic setup, choose it. Done.
   - If it shows a code snippet instead, copy the token value from it
     (the part after "token": ) into a GitHub repository VARIABLE named
     CF_WEB_ANALYTICS_TOKEN. The next scan adds it to every page.
   Use one or the other, not both.

D. Google Search Console (tells Google about all the new pages):
   https://search.google.com/search-console > Add property > Domain
   > stonks.run > verify through Cloudflare (it offers a one-click option),
   or copy the TXT record it shows into Cloudflare > stonks.run > DNS.
   Then Sitemaps > enter  sitemap.xml  > Submit.

E. AdSense consent message (required to show ads to EU/UK/Swiss visitors):
   AdSense > Privacy & messaging > European regulations > Create message
   > Publish. It uses the AdSense code already on every page.

F. Then request the AdSense review (Sites > stonks.run).


OPTIONAL SWITCHES (GitHub repository variables)
-----------------------------------------------
  SITE_HOST                 github (default) | cloudflare   - see PART 4
  CF_WEB_ANALYTICS_TOKEN    see PART 5C
  GOOGLE_SITE_VERIFICATION  only if Search Console asks for an HTML tag
                            instead of DNS: paste the content="..." value
  EXTRA_TICKERS             extra tickers to scan, comma-separated, e.g. the
                            Nasdaq-100 names the S&P lists miss (see the
                            screener review in the Stonks Run project)

Do NOT delete the "data" branch on GitHub. After the switch it holds the only
live copy of the screen history.


THE SCAN SCHEDULER (unchanged, for reference)
--------------------------------------------
The Cloudflare Worker "stonks-run-scheduler" starts each scan on time. Its
GitHub token expires about a year after Sept 2026. When the Worker's page
(https://stonks-run-scheduler.fscottevens.workers.dev) shows the token as
MISSING or ERROR:
  1. https://github.com/settings/personal-access-tokens/new
     Repository access: only trend-ledger. Permissions: Actions > Read and write.
  2. Cloudflare > Workers & Pages > stonks-run-scheduler > Settings >
     Variables and Secrets > edit GITHUB_TOKEN > paste > Deploy.
